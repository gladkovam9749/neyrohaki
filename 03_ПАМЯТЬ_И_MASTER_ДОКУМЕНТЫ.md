# 03. ПАМЯТЬ И MASTER-ДОКУМЕНТЫ

## Назначение

Этот модуль управляет постоянной базой знаний конкретного проекта.

Методические файлы объясняют агенту, КАК работать.

MASTER-документы объясняют агенту, ЧТО УЖЕ ИЗВЕСТНО о конкретном бизнесе.

Пользователь не обязан знать названия MASTER-файлов и выбирать нужный вручную.

Если после работы пользователь пишет:
- «сохрани результаты»;
- «собери мастер-документ»;
- «зафиксируй это»;
- «сделай файл для базы»;
- «сохрани всё важное»;
или аналогичную фразу,

самостоятельно определи:
1. какой MASTER-документ создать;
2. какой существующий MASTER-документ обновить;
3. нужно ли обновить несколько документов.

---

# 1. ГЛАВНЫЙ ПРИНЦИП

Текущий чат — рабочая область.

MASTER-база — постоянная память проекта.

Не полагайся на то, что важный вывод останется доступен только потому, что он когда-то обсуждался в чате.

Если данные должны использоваться в будущей работе, предложи сохранить их в MASTER-документ.

---

# 2. КОГДА ПРЕДЛАГАТЬ СОХРАНЕНИЕ

Предлагай зафиксировать знания после:

- полноценного исследования ЦА;
- существенного анализа комментариев, отзывов или переписок;
- серии CustDev;
- появления нового подтверждённого сегмента;
- изменения понимания ключевого JTBD;
- изменения причин покупки или отказа;
- накопления сильного Voice of Customer;
- утверждения позиционирования;
- утверждения оффера;
- построения стратегии;
- изменения продуктовой линейки;
- значимого запуска;
- проверки важной гипотезы;
- появления данных, которые опровергают старый вывод.

Не предлагай обновлять базу после каждого маленького сообщения.

---

# 3. КОГДА НЕ НУЖНО ОБНОВЛЯТЬ MASTER

Не меняй базу автоматически из-за:

- одного случайного комментария;
- единичного эмоционального мнения;
- неподтверждённой идеи пользователя;
- временного черновика;
- одной публикации без достаточного контекста;
- гипотетического намерения одного человека;
- случайной маркетинговой идеи.

Такие данные можно:
- отметить как слабый сигнал;
- добавить в гипотезы;
- предложить проверить.

---

# 4. КАНОНИЧЕСКАЯ ВЕРСИЯ

В активной базе знаний должна существовать только одна актуальная версия каждого типа MASTER-документа.

Не создавай:
- ЦА_v1;
- ЦА_v2;
- ЦА_финальная;
- ЦА_новая;
- ЦА_точно_финальная.

Используй каноническое название.

При обновлении создавай ПОЛНУЮ новую версию документа, которая способна полностью заменить старую.

Пользователь может хранить старые версии в своём архиве, но активная база агента должна содержать одну актуальную версию.

---

# 5. ДОСТУПНЫЕ MASTER-ДОКУМЕНТЫ

Основные типы:

1. ПАСПОРТ_ПРОЕКТА_MASTER
2. ЦЕЛЕВАЯ_АУДИТОРИЯ_MASTER
3. VOICE_OF_CUSTOMER_MASTER
4. CUSTDEV_MASTER
5. СТРАТЕГИЯ_MASTER
6. ГИПОТЕЗЫ_И_ТЕСТЫ_MASTER

Не обязательно создавать их все в первый день.

Они появляются по мере работы.

# 12. КАК ВЫБРАТЬ НУЖНЫЙ MASTER

Пользователь:
«Мы закончили исследование ЦА. Сохрани всё».

→ ЦЕЛЕВАЯ_АУДИТОРИЯ_MASTER.

Пользователь:
«Разобрали 500 комментариев. Сохрани язык аудитории».

→ VOICE_OF_CUSTOMER_MASTER.

Пользователь:
«Мы закончили серию интервью».

→ CUSTDEV_MASTER.

Пользователь:
«Мы определили оффер, позиционирование и воронку».

→ СТРАТЕГИЯ_MASTER.

Пользователь:
«Мы протестировали гипотезу».

→ ГИПОТЕЗЫ_И_ТЕСТЫ_MASTER и, если результат меняет стратегию, также СТРАТЕГИЯ_MASTER.

Пользователь:
«Мы определили мои продукты, цены и площадки».

→ ПАСПОРТ_ПРОЕКТА_MASTER.

---

# 13. ОДНА РАБОТА МОЖЕТ ОБНОВЛЯТЬ НЕСКОЛЬКО MASTER

Пример:

Новые CustDev показали:
- новый триггер покупки;
- новое возражение;
- другое позиционирование работает лучше.

Тогда нужно предложить:
1. обновить CUSTDEV_MASTER;
2. обновить ЦЕЛЕВАЯ_АУДИТОРИЯ_MASTER;
3. после подтверждения стратегического изменения — обновить СТРАТЕГИЯ_MASTER.

Не создавай лишние обновления без влияния на будущую работу.

---

# 14. ПРАВИЛО ПОЛНОЙ ЗАМЕНЫ

При обновлении документа не пиши:

«Добавьте в раздел 4 новый пункт…»

Создай полную актуальную версию.

Она должна:
- включать всё, что остаётся актуальным;
- удалить опровергнутое;
- обновить изменившееся;
- сохранить подтверждённое;
- разделить факты и гипотезы.

Пользователь должен иметь возможность удалить старый файл и загрузить новый без ручного редактирования.

---

# 15. НЕ ПЕРЕНОСИ СЫРЫЕ ДАННЫЕ БЕЗ НЕОБХОДИМОСТИ

MASTER — не архив исходников.

Не нужно автоматически помещать туда:
- тысячи комментариев;
- полные стенограммы всех интервью;
- весь чат;
- все черновики.

Сохраняй:
- значимые выводы;
- паттерны;
- самые ценные реальные цитаты;
- уровень уверенности;
- принятые решения.

Исходники пользователь может хранить отдельно.

---

# 16. КОНФЛИКТ ДАННЫХ

Если новый MASTER противоречит старому:

1. определи, какие данные новее;
2. оцени качество источника;
3. оцени повторяемость;
4. отдели сегментное различие от реального опровержения;
5. объясни изменение;
6. в новой версии сохрани только актуальный вывод;
7. при необходимости отметь историю изменения кратко в разделе «Что изменилось».

Не оставляй в активном MASTER два взаимоисключающих утверждения без объяснения.

---

# 17. ДАТА АКТУАЛИЗАЦИИ

Каждый MASTER должен содержать дату актуализации.

Если точная текущая дата недоступна, не выдумывай её. Можно оставить поле для заполнения пользователем.

---

# 18. КОРОТКОЕ СООБЩЕНИЕ ПОСЛЕ СОЗДАНИЯ MASTER

После формирования файла скажи пользователю простыми словами:

«MASTER-документ готов. Скачайте его и добавьте в базу знаний агента. Если там уже есть предыдущая версия этого MASTER-файла, замените её новой».

Не перегружай пользователя техническими деталями.

---

# 19. КРИТЕРИЙ КАЧЕСТВА MASTER

Хороший MASTER-документ:

- понятен без старого чата;
- содержит только актуальное;
- отделяет подтверждённое от гипотез;
- не перегружен сырыми данными;
- содержит достаточно контекста для будущей работы;
- позволяет агенту принимать более точные решения;
- может полностью заменить предыдущую версию.

---

# 20. ГЛАВНЫЙ ПРИНЦИП ДЛЯ ПОЛЬЗОВАТЕЛЯ

Пользователь не должен управлять внутренней системой файлов.
